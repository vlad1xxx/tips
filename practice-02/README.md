## 4. Модель данных и функции

**Модель задачи:** `{ id, title, completed, priority }`.

| Поле | Правило |
|---|---|
| `id` | `typeof id === "number"`, `Number.isSafeInteger(id)`, `id > 0`; уникален в списке (проверяется в `addTask`) |
| `title` | строка; после `trim()` длина 1…100; сохраняется очищенная строка |
| `completed` | только `boolean`; при создании `false` |
| `priority` | `"low"`, `"medium"` или `"high"`; по умолчанию `"medium"` |

**Файлы:**

| Файл | Ответственность |
|---|---|
| `src/data.js` | общий набор `demoTasks`, номер и задачи варианта |
| `src/task-service.js` | 9 экспортируемых функций + внутренние проверки `validateId`, `normalizeTitle`, `validatePriority`. Без `console.log` и без глобального состояния |
| `src/task-extra.js` | расширение — `searchTasks` |
| `src/main.js` | сценарии, вывод, обработка отказов |
| `checks.js` / `own-checks.js` | готовые и собственные проверки на `node:assert/strict` |

**Контракты:**

| Функция | Успех | Ошибка |
|---|---|---|
| `createTask(id, title, priority = "medium")` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById(tasks, id)` | объект задачи (`find`) | `undefined` |
| `getPendingTasks(tasks)` | новый массив (`filter`) | — |
| `getTaskTitles(tasks)` | новый массив строк (`map`) | — |
| `getTaskStats(tasks)` | `{ total, completed, pending, progress }` | — (для `[]` все поля `0`) |
| `addTask` (spread массива) / `setTaskCompleted`, `renameTask` (`map` + spread объекта) / `removeTask` (`filter`) | `{ ok: true, tasks: новыйМассив }` | `{ ok: false, error }` |

**Почему id не равен индексу:** индекс — текущая позиция в массиве и меняется после удаления или вставки; `id` — постоянный идентификатор записи. В `demoTasks` задача `id = 4` лежит по индексу 1, а `demoTasks[4]` вообще `undefined`.

**Почему getTaskStats возвращает число, а не строку с процентом:** число можно дальше сравнивать и использовать в расчётах; форматирование (`toFixed(1)` возвращает строку) — задача слоя вывода. Так одна функция подходит и для консоли, и для будущей страницы.

**Какие объекты копируются при изменении задачи:** создаётся новый массив (`map`) и новый объект только изменяемой задачи (`{ ...task, completed }`). Неизменённые объекты переиспользуются — их свойства не меняются, поэтому это безопасно.

## 9. Вывод

По сравнению с ПР1 логика вынесена в функции, которые **возвращают** результат, а не печатают его: `main.js` решает, как показать данные, а `task-service.js` можно будет без изменений использовать из обработчиков событий на странице (ПР3). Данные представлены массивом объектов, операции изменения работают иммутабельно — возвращают новый массив и новый объект изменённой задачи, что проверено снимками до/после и сравнением ссылок. Наиболее показательная ошибка — пропущенный `return` в стрелочной функции с фигурными скобками: код выглядит правильно, исключения нет, но результат `undefined`.

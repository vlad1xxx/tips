## 4. Задание 1 — одна программа, две среды

Файл `js/hello.js` запущен в Node.js и в браузере (через `index.html`).

| Среда | Где виден вывод | `typeof document` |
|---|---|---|
| Node.js | В терминале | `undefined` — объект `document` существует только у браузерной среды, у Node.js нет DOM |
| Браузер | В DevTools → Console (не на странице) | `object` — браузер предоставляет доступ к DOM через глобальный объект `document` |

Программа и её вывод одинаковы для первых четырёх строк; отличается только последняя строка (`typeof document`), что и показывает разницу между языком JavaScript и средой его выполнения.

## 5. Задание 2 — типы и преобразования

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"` | `"82"` | `string` | Один из операндов `+` — строка, поэтому выполняется конкатенация, а не арифметика |
| `"8" - 2` | `6` | `6` | `number` | `-` не имеет строкового смысла, строка приводится к числу |
| `Number("8") + 2` | `10` | `10` | `number` | Явное преобразование строки в число перед сложением |
| `"12" > "3"` | `false` | `false` | `boolean` | Строки сравниваются посимвольно как текст: `"1"` меньше `"3"` |
| `12 === "12"` | `false` | `false` | `boolean` | Строгое равенство не приводит типы операндов друг к другу |
| `Number("")` | `0` | `0` | `number` | Пустая строка преобразуется в `0`, а не в `NaN` |
| `Number("text")` | `NaN` | `NaN` | `number` | Строка не может быть разобрана как число |
| `Boolean("false")` | `true` | `true` | `boolean` | Это непустая строка; `Boolean()` не анализирует текст как команду |
| `typeof null` | `"object"` | `"object"` | `string` | Исторически закреплённая особенность JavaScript, `null` при этом остаётся примитивом |
| `typeof NaN` | `"number"` | `"number"` | `string` | `NaN` — особое значение числового типа |

## 7. Отладка (`debug.js`)

Иллюстрация остановленной программы: [`screenshots/debug-breakpoint.png`](./screenshots/debug-breakpoint.png).

**Исходный (ошибочный) вывод:**

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | `Выполнено: 32`, `Осталось: -24` вместо `5` и `3` | `completedText + additionalText` — оператор `+` над строками `"3"` и `"2"` выполняет конкатенацию (`"32"`), а не сложение | Явное преобразование через `Number()` перед сложением: `Number(completedText) + Number(additionalText)`, аналогично для `remainingTasks` | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла | `Контрольная сумма: 6` вместо `10` | Условие `taskNumber < 4` останавливает цикл на `taskNumber = 3`, последнее слагаемое `4` не учитывается | Изменена граница на `taskNumber <= 4` | `Контрольная сумма: 10` |

**Итоговый (исправленный) вывод:**

```text
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

Точка останова ставилась на строке вычисления `completedTotal`; до её выполнения в Scope проверялись значения и типы `completedText`/`additionalText` (оба — `string`), после шага Step Over — значение и тип `completedTotal`. Аналогично точка останова внутри цикла показала, что `taskNumber` доходит только до `3` при старом условии.

## 8. Вывод

Освоен базовый цикл разработки на JavaScript: написание кода, запуск в Node.js и в браузере, проверка обычных, граничных и некорректных входных данных, использование точек останова для поиска логической ошибки. Наиболее показательной оказалась ошибка в `debug.js` — оператор `+` над строками не выбрасывает исключение и не выглядит подозрительно, но даёт содержательно неверный результат (`"3" + "2" = "32"`, а не `5`); без явной проверки типов и данных такую ошибку легко пропустить, полагаясь только на отсутствие ошибок выполнения.
